# ADR-0001: Clean-room and system boundaries

- Status: accepted
- Date: 2026-08-03
- Deciders: Omar Ibrahim

## Context

The mission was motivated partly by a public C experiment for running Kimi K3
with constrained memory. Studying a system can inform requirements, but using
its implementation, presentation, or experimental claims would obscure what
this project demonstrates and could create attribution or licensing mistakes.

## Decision

RunnelMoE is specified and implemented independently.

The allowed prior-art pass records only:

1. repository identity, pinned commit, license, and public file metadata;
2. externally observable problem statements and architectural categories;
3. primary model facts from the model publisher's report; and
4. questions that RunnelMoE must answer with its own experiments.

No upstream source, pseudocode, prose, fixture, binary format, test vector,
script, image, diagram, directory layout, command-line interface, or benchmark
number enters this repository. Contributors must not use upstream identifiers
as temporary names. If a future change genuinely requires third-party code,
that change stops until exact files, license obligations, notices, provenance,
and modifications are reviewed and documented.

The implementation boundary is:

- **safe control plane:** Rust, with no unsafe code in parser and scheduler
  crates;
- **kernel boundary:** a small versioned C ABI, added only with scalar parity,
  runtime ISA checks, sanitizer coverage, and explicit ownership/alignment
  rules;
- **oracle boundary:** independent Python/PyTorch equations and fixture
  generation, never imported by the production runtime;
- **adapter boundary:** model architecture and tensor-name mapping are data and
  traits, not assumptions baked into storage or scheduling;
- **evidence boundary:** project results come only from committed commands and
  raw records generated by RunnelMoE.

## Consequences

This duplicates some work deliberately and may delay feature breadth. In
return, reviewers can attribute every engineering choice and measurement to
this project. Kimi K3 compatibility is not implied; it would be a separately
gated optional adapter.
