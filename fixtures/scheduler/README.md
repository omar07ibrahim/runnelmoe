# Scheduler correctness fixtures

`sampling-v1.json` is the committed cross-language vector set for the seeded
sampling contract in ADR 0007. It is generated by the separately structured,
Python-standard-library implementation in `oracle/sampling.py`; that module
does not import, inspect, or execute the Rust sampling implementation.

The artifact uses the closed schema `runnel.sampling-vectors/1`. Binary32
inputs are lowercase, fixed-width hexadecimal bit patterns, so NaNs,
subnormals, and one-ULP boundaries retain exact custody. Binary64 diagnostics
use canonical `float.hex()` strings. Integer RNG state and output words use
fixed-width hexadecimal strings rather than JSON numbers.

Frozen identity:

- semantic vector ID (SHA-256 of the canonical document without `vector_id`):
  `sha256:76a258c07a32e1a2dc61ad5d4d59827cfca469372e25b052bcf1f0bde38d6ccb`;
- complete file SHA-256:
  `5db404a505c5560654c04a77435485e176fe5c2bf868d3aaf4ad1b543ebdda82`;
- cases: 4 SplitMix64 transitions, 7 complete sampling previews, 5 direct
  categorical boundaries, and 14 invalid-input cases.

The complete cases cover stable logit ties, `top_k = 1`, exact/neighboring
binary32 top-p boundaries around one half, the smallest positive binary32
temperature, and an underflowed nonmaximum softmax weight. Direct categorical
cases freeze `u = 0`, `nextafter(0, 1)`, `u = 0.5`, `nextafter(1, 0)`, and a
final cumulative value one ULP below one that requires the last-candidate
rounding fallback. Invalid cases cover empty logits, every nonfinite-logit
class, invalid temperatures, top-k bounds, and invalid/nonfinite top-p values.

From the repository root, verify the committed bytes without rewriting them:

```console
python -m oracle.sampling --check
python -m unittest oracle.tests.test_sampling -v
```

Regeneration is a deliberate review action:

```console
python -m oracle.sampling --write
```

Any accepted regeneration must update both frozen digests above and the
literal assertions in `oracle/tests/test_sampling.py`. The tests reject stale
semantic identities, noncanonical JSON, self-consistent alternate vectors,
and any difference from independent regeneration.

Rust cross-language tests should compare state transitions, random words,
ordered token IDs, retained token IDs, and chosen tokens exactly. They should
reconstruct every binary32 input from its raw bits. Binary64 diagnostics are
for diagnosis and use a maximum four-ULP comparison, fixed before M5 timing:
`math.exp` is intentionally not presented as bitwise portable across all libm
implementations.
